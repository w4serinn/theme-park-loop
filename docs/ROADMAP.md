## ページ制作の品質方針

evolveループはこの方針を毎サイクル遵守すること:

- **アトラクション数**: エリアの規模・性格に合わせて自由に設定する(2〜7件程度)。
  全エリアで同じ件数にならないよう、意図的にバラつかせること。
- **テキスト**: 各項目の文章量・視点・トーンを変え「コピーした感じ」を避ける。
  固有名詞・具体的な数字・エピソードを含めて世界観を作り込む。
- **レイアウト多様化**: セクションを作るたびにカードグリッドで解決しない。
  prose+aside・タイムライン・dl定義リスト・横スクロール・大きな単一ビジュアル等、
  内容に合った形を先に検討してから実装すること。カードは「複数の同格アイテムを
  並べる」ときだけ選ぶ。
- **エフェクトの意味**: hover・transition・animation には必ず目的を持たせる。
  「クリックできる」「状態が変わる」「注目してほしい」のどれかを伝えるために使う。
  リンクでないカード・装飾的な要素への `translateY` や border-color 変化は使わない。
  リンクカードには arrow の移動・border 明度変化など「行き先がある」ことを示す
  表現を優先する。
- **素材の積極依頼**: `docs/ASSET_REQUESTS.md` への素材依頼は hero 画像だけに限らない。
  セクション背景テクスチャ・エリアアイコン・インライン挿絵・カードサムネイルなど、
  「小さいイラストでも世界観が明確に上がる」と判断したら即座に依頼すること。
  ユーザーは依頼があれば自分で作ると言っている。躊躇せず提案する。
- **色・素材の提案**: PALETTE.md への色提案と ASSET_REQUESTS.md への素材依頼は、
  「あると体験が明確に良くなる」と思ったら積極的に行うこと。1サイクル1提案が目安。
- **テキストコントラスト**: テキスト色は `var(--brass)` または
  `color-mix(in oklch, var(--brass) 75%以上, transparent)` を使う。
  `var(--ink)` と混ぜると暗くなるため、文字色に `var(--ink)` を混ぜてはならない。
  `var(--emerald)` は暗い深緑なので、dark背景上のテキスト色に使ってはならない。
- **完了の基準を上げる**: アトラクション追加・インタラクション・画像対応・
  テキスト充実が揃って初めて`完了`とする。骨格を作っただけで`完了`にしない。

      誤認」と判断してクローズしたが、実画像反映後の現在も再現することを
      人間が確認済みのため再オープン。前回の判断は誤りだった。
      新たな仮説: `category-card__visual` は高さ140px固定・カード幅は
      280px前後で、box比率(約2:1)が画像の実比率(約5:1)よりずっと
      正方形に近い。`background-size: cover` はこの場合、画像を高さ基準で
      拡大するため画像の縦方向は一切トリミングされず全体がそのまま表示される
      (ヒーロー側と違い、こちらは「クロップされすぎ」ではなく「画像の上下が
      そのまま見えている」状態)。そのため、生成画像自体の上下(天井际・床際等)
      が暗い構図であれば、CSSの指定に関わらず暗い帯として見える可能性がある。
      ヒーロー側と同じaspect-ratio調整が有効かは未検証。実際の見た目
      (スクリーンショット等)を確認してから対応方針を決める。

## 技術メモ

- **ニュース区切り線の color-mix**: `color-mix(in srgb, var(--brass) 20%, transparent)` は sRGB でブラックと混合するため、インク背景上では実質不可視になる。ニュース項目が実装される際は `oklch` 色空間か 35〜40% に調整すること。
- **エリアページのサムネイル**: 学院内探索の7エリア、購買部の一覧カード(category-card__visual、中央5種+エリア別14種)、学食・喫茶室のエリアタブカード(dining-venue-feature__visual)は全て実画像を反映済み(既存のhero画像を`background-image`で再利用)。CSSグラデーションはフォールバック背景として残置。
- **インタラクティブ要素の方針**: JS は src/ 以下に純粋な関数として実装し、HTML から script タグで読み込む。DOM 操作のみのスクリプトは pages/ に置かない。
