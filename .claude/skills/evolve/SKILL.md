# evolve: 王立魔法学院アルノルド サイト 自動開発サイクル

以下の手順で **1周だけ** 実行してください。
1周 = 「ROADMAP.mdから次のタスクを1つ選ぶ → 実装 → テスト → コードレビュー →
ドキュメント更新 → commit → push → バックログ更新」です。

---

## 0. 事前チェック

- 作業ブランチは必ず `evolve/cycle-<連番>`。mainにいたら最新化してブランチを作る。
  **人間がmainに取り込むまでは、同じ`evolve/cycle-<連番>`ブランチに複数サイクル分の
  コミットが積み重なるのが正常な動作である**(サイクルごとに新しいブランチを作る
  必要はない)。
- サイクル開始時に `git fetch origin` を実行し、現在のブランチの最新コミットが
  すでに `origin/main` に取り込まれているか確認する
  (`git merge-base --is-ancestor HEAD origin/main` などで判定できる)。
  取り込まれていれば、そのブランチは`docs/ROADMAP.md`のページ完了を検出した
  GitHub Actionsによって**すでに自動マージ・削除済み**なので、
  `git switch main && git pull` で最新化し、新しい `evolve/cycle-<連番+1>`
  ブランチを作り直してから、通常の手順(1節以降)に進む。
- 前回サイクルが未完了(実装済みだがテスト未了、`partial`のまま等)の形跡があれば、
  新しいタスクに着手せず**続きから再開**する。
- ユーザーの手作業らしき変更が混ざっていたら、何もせず報告して終了する。
- `docs/ROADMAP.md` の「世界観」セクションを必ず確認し、コアカラー・パーク名・
  コンセプトから外れた実装をしないこと(世界観は既に確定済み)。

## 1. タスク選定

`docs/ROADMAP.md` を以下の優先順で読み、次のタスクを1つ選ぶ。

1. 「バグ修正(最優先)」セクションの未対応項目
2. 現在進行中のページの未完了サブタスク(上から順)
3. 未着手ページの最初のサブタスク
4. 上記が全て`blocked`/承認待ちで進められない場合、または特に見た目の粗さが
   気になった場合のみ「0. 共通パーツ(ヘッダー/フッター)」に着手してよい
   (特定ページの完成を左右しないため、最優先にはしない)

- 選んだ候補が `blocked`、`[asset-pending]`(素材待ち)、または
  `docs/PALETTE.md` / `docs/ASSET_REQUESTS.md` の承認待ちで今は着手できない状態の場合、
  そのタスクは一旦スキップし、同じページの次の未完了サブタスク(それも無ければ次の優先順位の
  候補)に進む。依存が解消された(承認された・素材が配置された)ことを確認できたら、
  そのサイクルで再訪してよい。
- **サイズLの項目には着手しない**。S/Mの子項目に分割してROADMAPを書き換えるだけで
  1サイクルとしてよい。
- **1サイクル=1タスク**を厳守する。1ページは複数サイクルに分けて完成させる。
  実装中に別の改善点を見つけても直さず、ROADMAP.mdにtodoとして追記するだけにする。
- 一覧系ページ(学院内探索・購買部・学食)は「一覧ページ→エリア/カテゴリページ」の
  2階層までとする。個別アトラクション・商品・メニューの詳細はエリアページ内で
  モーダルまたはアンカーで表現し、3階層目のページを作らない。
  エリア・カテゴリの数自体は自由に増やしてよい。
  実装の計画時点で3階層目が必要そうだと気づいた場合は、実装せずに
  `docs/ROADMAP.md` の「新規ページ提案」に提案を追記するだけにしてよい。
  ただしこれは早期発見できた場合の簡易チェックであり、必須ではない。
  最終的な検出・修正は4節の `local-review` が確実に担う。
- ROADMAPのタスクが尽きたら、既存の実装を見て新しいタスク案を3〜5個
  「今後のタスク候補」に追加し、その中から1つ着手する。
- 新しいページ自体を追加したくなった場合は、実装せず
  「新規ページ提案」セクションに提案を追記するだけにする(承認制)。

## 2. 実装

- 選んだタスクをテスト可能な最小単位で実装する。
- ロジック(計算・状態管理など)は必ず `src/logic.js` に実装し、DOM操作と混在させない。
- 色は必ず `styles/tokens.css` で定義済みのCSS変数(`var(--brass)` 等)を使う。
  新しいアクセント色が必要な場合は次の手順を取る:
  1. 実装にはコアカラー(`--brass`/`--emerald`/`--ink`/`--ember`)のみを使って一旦進める
  2. `docs/PALETTE.md` の「提案中」に、色・使用予定ページ・理由を追記する
  3. 承認(人間が「承認済み」に移動)されるまで、その新色は実装に使わない
- ヘッダー・フッターは各ページのHTMLに直接書かず、`<!-- HEADER -->` / `<!-- FOOTER -->`
  のプレースホルダーを使う(`npm run build` が `partials/` の内容を合体させる)。

### タスク実行中にスコープが大きすぎると判明した場合

見積もり(S/M)を超えて作業が拡大しそうだと判明した場合、そのまま続けず以下を行う。

1. その時点で完結し、テストが通る最小の成果があれば、それだけを今回のコミット対象とする
2. 残りの作業を `docs/ROADMAP.md` の新しい子タスクとして書き出す(サイズを再見積もりする)
3. 該当タスクの status を `partial` にして理由を記載し、サイクルを終える
4. 完結した成果が無い場合は、変更を `git stash` で退避し、`blocked` と同様の扱いとする

### 画像・音声素材が必要な場合

実装に画像や音声が必要だが、配置先パスにファイルが存在しない場合:

1. そのタスクは実装せず、`docs/ASSET_REQUESTS.md` の「依頼中」に依頼を1件追記する
   (用途・配置先パス・想定ツール[Midjourney/ChatGPT/Irodori-TTSのいずれかを実装内容に
   応じて判断]・提案プロンプトまたは台詞テキストを含める)
2. 代わりにプレースホルダー(枠線+ラベル表示、または無音)で実装を進め、
   その他の部分(レイアウト・レスポンシブ対応等)は通常どおり完了させる
3. コミットメッセージに `[asset-pending]` を含める
4. 依頼済みの素材が配置先パスに存在するようになったら、次にこのタスクを再訪した際に
   プレースホルダーを実ファイルに差し替える

## 3. テスト・lint

以下を順に実行し、**全て成功させてからコミットする**。

```bash
npm run lint
npm run lint:css
npm run test
npm run build
```

失敗したら修正して再実行。**2回連続で同じ原因で失敗して解決の目処が立たない場合**は:

- 変更を `git stash` で退避
- `docs/ROADMAP.md` の該当項目を `blocked` にして理由を記載
- そのことだけをコミットしてサイクルを終える

## 4. コードレビュー

テストが通ったら、`local-review` skillを実行し、まだcommitしていない差分
(ワーキングツリー・新規ファイル含む)を客観的にレビューする。

指摘への対応方針:

- 今回の変更が原因の不具合 → その場で修正し、テスト一式を再実行してから同じコミットに含める
- スコープ外・既存の別問題・優先度の低い改善 → 直さず `docs/ROADMAP.md` にtodoとして追記する
- 誤検知・対応不要 → 対応せず、サイクル終了時の報告でその旨に触れる

`local-review` が使えない場合はレビューをスキップし、サイクルは止めない。

## 5. ドキュメント更新

- 変更内容に応じて `README.md` やページ説明を同一サイクルで更新する
- ページのサブタスクが全て完了した場合、`docs/ROADMAP.md` の該当ページの status を
  `完了` にし、`docs/roadmap-done.md` へ該当ページの記述を移動する

## 6. コミット・プッシュ

- 1サイクルの成果を必ず1コミットにまとめ、`evolve/cycle-<連番>` ブランチにpushする
- コミットメッセージ形式: `feat: <内容>` / `fix: <内容>` / `docs: <内容>`
  (素材待ちの場合は末尾に `[asset-pending]` を付与)

## 7. バックログ更新・サイクル終了報告

- 今回選ばなかったタスク、新たに見つけた改善点をROADMAP.mdに反映する
- 以下の内容を `docs/cycle-log.md` に追記する:

```
## YYYY-MM-DD HH:MM
- 実装: (実装した内容)
- レビュー: OK / 指摘N件対応 / スキップ
- lint: ✓ / lint:css: ✓ / test: ✓ / build: ✓
- 次回予定: (次のサイクルで着手予定の項目)
- blocked / partial: なし or (内容)
- asset-pending: なし or REQ-XXX
```

追記後、同じ内容をターミナルにも表示する。

## 禁止事項

- mainへの直接commit/push/merge(取り込みは人間がレビュー後に行う)
- PRの作成・マージ(`gh pr create`、`gh pr merge`等)を自分で実行すること。
  取り込みの判断と実行は必ず人間が行う
- 履歴改変(`rebase -i`、force push、`reset --hard`) — evolveブランチ上でも禁止
- テストが通っていない状態でのcommit/push
- ROADMAPにない大規模リファクタリング
- コアカラー以外の色を、`docs/PALETTE.md` での承認前に実装で使うこと
- 一覧系ページに3階層目のページを新設すること
- ROADMAPを経由しない新規ページの追加
