# local-review: ワーキングツリー差分の客観レビュー

まだcommitしていない差分(ステージ済み・未ステージ・新規ファイル含む)を対象に、
実装した視点から離れて、客観的なコードレビューを行ってください。

## 観点

- 今回の変更が原因で発生した不具合(表示崩れ、JSエラー、アクセシビリティ低下など)
- 既存の見た目・機能への意図しない影響
- 世界観・デザインの一貫性
  - コアカラー(`--brass`/`--emerald`/`--ink`/`--ember`)以外の直接色指定が無いか
  - `docs/PALETTE.md` で未承認のアクセント色が実装に使われていないか
  - ヘッダー・フッターが `<!-- HEADER -->` / `<!-- FOOTER -->` のプレースホルダー経由に
    なっているか(独自の`<header>`/`<footer>`タグを直接書いていないか)
- 一覧系ページで3階層目のページが新設されていないか(2階層ルールの逸脱)
- テストでは検出できない「使い勝手」の違和感(操作導線、文言のわかりにくさ等)

## 出力形式

指摘事項ごとに以下を出力すること:

- ID(例: A-1, B-1)
- 重要度(high/medium/low)
- 内容
- 今回の変更が原因か、既存の別問題か

## 分類の目安

- 今回の変更が原因の重大な不具合 → 呼び出し元(evolveサイクル)がその場で修正
- スコープ外・既存の別問題 → `docs/ROADMAP.md` へtodo追記対象として報告
- 誤検知・対応不要 → その旨を明記

### 2階層ルール違反(3階層目の新設)を見つけた場合の具体的な対応

これは「今回の変更が原因の不具合」として扱い、その場で以下の手順で修正すること。

1. 新設された3階層目のページファイルをコミット対象から外す(削除、またはstashする)
2. そのページで作ろうとしていた内容を、`docs/ROADMAP.md` の「新規ページ提案」に
   提案として書く(どのエリアの、何を、なぜ独立ページにしたいか)
3. 元のタスクは、2階層に収まる範囲(モーダルやアンカーでの表現)で実装し直す。
   収まらない場合は、そのタスク自体を `partial` にして理由を記載する
